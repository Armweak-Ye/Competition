## 项目简介

机器人需要在规定场地内自主完成 **二维码识别 → 排爆 → 反恐打靶 → 人质救援** 的全流程。视觉系统不参与导航决策，只负责「看」：

- 读取二维码，解析任务参数
- 定位排爆物、排爆桶、反恐靶标、救援目标
- 判断目标是否进入「夹取点位」，用 `flag` 通知主控执行动作
- 巡线时提供赛道中心坐标，辅助直线行驶

**核心设计思想：把「位置」和「朝向」解耦。** 车头朝向由陀螺仪闭环，视觉只提供横向位置参考；纠偏时车头不动，只用麦克纳姆轮横向平移。

## 系统架构

状态机架构：主控发命令切换模式，每个模式内部持续采集—识别—上报，直到收到新命令。

```
上电
 │
 ├─ 初始化 UART / 补光灯常亮 / LED 闪三下就绪
 │
 └─ 空闲等待（LED 灭）
      │
      ├── 0x01 QR ────── 二维码扫描      → A3 B3 01 d1 d2 d3 C3
      ├── 0x02 + 颜色 ── 排爆物定位      → A3 B3 02 X Y flag C3
      ├── 0x05 ───────── 排爆桶定位      → A3 B3 05 X Y flag C3
      ├── 0x03 + 颜色 ── 反恐靶标定位    → A3 B3 03 X Y flag C3
      ├── 0x04 + 形状 ── 救援目标识别    → A3 B3 04 X Y flag C3
      └── 0x06 ───────── 巡线            → A3 B3 06 X 00 flag C3
```

模式内收到「其他命令」即退出并切换，无需额外握手。

## 通信协议

### 命令字

| 命令 | 值 | 参数 | 说明 |
|------|-----|------|------|
| `CMD_QR` | `0x01` | 无 | 二维码扫描 |
| `CMD_BOMB` | `0x02` | 1 字节颜色：1=红 2=绿 3=蓝 | 排爆物定位 |
| `CMD_TARGET` | `0x03` | 1 字节颜色：1=红 2=绿 3=蓝 | 反恐靶标定位 |
| `CMD_RESCUE` | `0x04` | 1 字节形状：1=圆柱 2=圆锥 3=腰鼓 | 救援目标识别 |
| `CMD_BIN` | `0x05` | 无 | 排爆桶定位 |
| `CMD_LINE` | `0x06` | 无 | 巡线 |

> 带参数的命令需**连续下发两个字节**，OpenMV 收到命令字后等待 50ms 收取参数。

### 帧格式（固定 7 字节）

帧头 `0xA3 0xB3`，帧尾 `0xC3`，中间 3 个数据字节。

```
QR:     A3 B3 01 d1 d2 d3 C3        d1~d3 = 三位任务数字
BOMB:   A3 B3 02 X  Y  flag C3      排爆物中心 + 到位标志
TARGET: A3 B3 03 X  Y  flag C3      靶心坐标 + 到位标志
RESCUE: A3 B3 04 X  Y  flag C3      人质坐标 + 到位标志
BIN:    A3 B3 05 X  Y  flag C3      排爆桶坐标 + 到位标志
LINE:   A3 B3 06 X  00 flag C3      赛道中心 + 有效标志
```

**`flag` 语义**

| 帧 | flag=1 的含义 |
|----|--------------|
| BOMB / TARGET / BIN | 目标中心落入「夹取点位窗口」 |
| RESCUE | 模板匹配成功 **且** 匹配中心 X 落入夹取窗口（只看 X） |
| LINE | 本帧找到赛道（0 表示丢失，主控应保持上次纠偏量） |

### 坐标量化

所有坐标都压缩到 **0~255 单字节**，主控按分辨率还原：

| 模块 | 分辨率 | 量化公式 | 还原公式 |
|------|--------|---------|---------|
| QRcode | **HD 1280×720** | 不发坐标，只发数字 | — |
| bomb | QVGA 320×240 | `X = raw×255//319`，`Y = raw×255//239` | `raw = X×319//255` |
| target | QVGA 320×240 | 同上 | 同上 |
| rescue | VGA 640×480 | `X = raw×255//639`，`Y = raw×255//479` | `raw = X×639//255` |
| line | QVGA 320×240 | `X = raw×255//319` | `raw = X×319//255` |

> ⚠️ 各模块**分辨率不同**，同一个物理位置在 QVGA 与 VGA 下的数值差约 2 倍，标定时切勿混用。

## 模块详解

### `QRcode.py` — 二维码识别

- **分辨率**：GRAYSCALE + **HD (1280×720)**（长焦镜头下 QR 在画面里占比小，用高分辨率补像素）
- **识别方式**：OpenMV 内置 `find_qrcodes()`
- **ROI**：`QR_ROI = (392, 200, 400, 370)`，只在框内扫描；二维码必须**完整**落在框内
- **校验**：payload 必须是 3 位纯数字，且每一位在 1~3 之间
- **兜底**：`QR_ROI_FALLBACK_FULL` 控制 ROI 内没找到时是否整帧再扫一次
- **调试**：`QR_DRAW_DEBUG` 画 ROI 灰框与实际识别白框，并 `print` 出 payload

> ROI 尺寸约 400×370，是全帧的 16%，扫描速度比整帧快数倍。

### `bomb.py` — 排爆物 & 排爆桶定位

- **分辨率**：RGB565 + QVGA
- **曝光**：初始化时先让自动曝光收敛，读出 `get_exposure_us()` 后按 `EXPOSURE_SCALE` 比例下调并锁定
  - 排爆物 `EXPOSURE_SCALE = 0.7`（防红色过曝）
  - 排爆桶 `BIN_EXPOSURE_SCALE = 0.9`（防阴影被误检为黑色目标）
- **排爆物 `detect_bomb()`**
  - LAB 阈值分割 → `find_blobs` → 按「圆形度 > 0.4 且面积最大」选目标
  - 输出中心坐标 + 夹取点位标志
- **排爆桶 `detect_bin()`**
  - 黑色阈值分割后做**三重几何筛选**：
    1. 宽高比 0.7~1.4（近似正圆）
    2. 圆形度 > 0.35
    3. **不贴画面边缘**（贴边的大暗块是桌面/地面阴影）
  - 筛不出可信目标就返回「未找到」，宁可漏检不误检
  - 检测前执行 `img.lens_corr(1.5)` 做畸变校正

### `target.py` — 反恐靶标定位

- **分辨率**：RGB565 + QVGA
- **ROI**：`TARGET_ROI = (103, 100, 77, 72)`，仅占全帧约 7%
- **流程**
  1. 按外环颜色分割出色块（取面积最大）
  2. 在色块邻域内做霍夫圆检测（`threshold=3500, r_min=3, r_max=45`）
  3. **距离门**：只接受圆心到色块几何中心距离 ≤ 色块尺寸 1/6 的圆
  4. 通过筛选的圆里取**离色块中心最近**的一个作为靶心
  5. 一个可信圆都没有 → 退回色块几何中心（同心圆，色块中心即靶心）

距离门是抑制木纹、阴影假圆的关键——同心圆的圆心必然重合，假圆必然偏离。

### `rescue.py` — 救援目标形状识别

- **分辨率**：GRAYSCALE + VGA
- **两阶段策略**
  1. **粗定位**：高亮阈值提取白色目标，取其中心引导小车横向对位
  2. **精确认**：进入 ROI 后在色块邻域内做归一化互相关（NCC）模板匹配，确认形状
- **模板**：`01.pgm`（圆柱）/ `02.pgm`（圆锥）/ `03.pgm`（腰鼓），赛前在**夹取距离**下采集
- **关键参数**

  | 参数 | 当前值 | 作用 |
  |------|--------|------|
  | `MATCH_THRESHOLD` | 0.78 | 相似度阈值 |
  | `MATCH_STEP` | 10 | 搜索步长（帧率与精度的平衡点） |
  | `MATCH_ROI_MARGIN` | 50 | 搜索框在色块四周外扩量 |
  | `ROI` | (183, 188, 232, 269) | 允许启动匹配的判定区 |
  | `GRAB_X/Y` | 277~297 / 282~302 | 夹取点窗口 |

- **`flag=1` 条件**：模板匹配成功 **且** 匹配中心 X 落在 `GRAB_X_MIN ~ GRAB_X_MAX`（Y 由底盘编码器走固定路径保证，不参与判定）
- **两个容易踩的坑**
  - 模板**不能**用 `copy_to_fb=True` 加载，否则会被 `sensor.snapshot()` 覆盖
  - 模板与运行时必须使用**同样的畸变校正状态**

### `line.py` — 巡线辅助

- **分辨率**：RGB565 + QVGA（对帧率要求高于分辨率）
- **ROI**：`(10, 158, 304, 50)` —— 画面下方的一条水平窄带
- **算法**
  1. 在 ROI 内按紫色 LAB 阈值 `find_blobs`
  2. 取所有紫色块的**整体跨度**（最左 → 最右），求中点
  3. 量化成 0~255 上报

取「整体跨度」而非单个最大块质心，是为了赛道被反光切断时仍能还原真实中心。

> 只看近处窄带而不看远处，一方面避开透视畸变，另一方面让测量值尽量只反映**横向位置**而不混入车头朝向误差。

## 关键算法设计

### 1. LAB 色彩空间

所有颜色识别使用 LAB 而非 HSV。LAB 将亮度（L）与色度（a、b）分离，补光强度波动、自动增益介入时色度分量更稳定，红/绿/蓝三色更容易稳定分离。

### 2. 几何特征筛选

颜色阈值分不开的干扰（阴影、木纹、反光），用几何先验过滤：

- 圆形度（`blob.roundness()`）
- 宽高比
- 是否贴画面边缘
- 尺寸下限（`pixels_threshold` / `area_threshold`）

**把物理先验（对称性、贴边性、尺寸约束）写进算法，往往比单纯调阈值更有效。**

### 3. 霍夫圆距离门

靶标是同心圆：内圆、外圆、色块几何中心的圆心应当重合。因此在霍夫圆结果中，只保留「圆心到色块中心距离 ≤ 色块尺寸 1/6」的圆，伪圆被直接淘汰。

### 4. 模板匹配的性能权衡

`find_template` 的耗时近似：

```
耗时 ≈ 候选位置数 × 模板像素数
候选位置数 ≈ ((2 × MATCH_ROI_MARGIN) ÷ MATCH_STEP)²
```

变焦放大后模板与目标同步变大，**候选位置数基本不变，只有模板像素数增加**（线性增长，非平方）。因此调 `MATCH_STEP` 是最有效的加速手段：

| MATCH_STEP | 相对耗时 | 定位精度 |
|-----------|---------|---------|
| 2 | 1×（极慢） | ±2 px |
| 8 | ~1/16 | ±8 px |
| 10 | ~1/25 | ±10 px |
| 16 | ~1/64 | ±16 px |

### 5. 曝光控制

上电先让自动曝光收敛，读取当前曝光值后按比例下调并锁定，同时锁定自动增益与白平衡：

```python
sensor.skip_frames(60)
auto_exp = sensor.get_exposure_us()
sensor.set_auto_exposure(False, exposure_us=int(auto_exp * EXPOSURE_SCALE))
sensor.set_auto_gain(False)
sensor.set_auto_whitebal(False)
```

好处：换场地不用改代码，自动曝光先适应环境，再按固定比例压暗，抑制补光直射造成的过曝。

## 现场标定流程

### 1. 颜色阈值（每个赛区独立标）

OpenMV IDE → `Tools → Machine Vision → Threshold Editor`，在**实际场地光照**下对着实物调，直到二值图中目标连续、背景全黑。

- 排爆物 / 靶标 / 赛道：用 LAB 的 a、b 通道入手
- 排爆桶：黑色判断看 L 通道

### 2. 识别 ROI

打开各模块的绘制开关（`QR_DRAW_DEBUG`、`TARGET_DRAW_ROI` 等），看框是否罩住目标。ROI 要保证目标**完整**在框内，四周留 20~30px 余量。

### 3. 夹取点位

1. 把车摆到「机械臂能夹到」的位置
2. 看画面里目标中心（白框十字）与夹取点（绿十字）的偏差
3. 读标签上的 `X=.. Y=..`，把 `GRAB_X/Y_MIN/MAX` 设成该坐标 ±2~5
4. 标签出现 `HIT` 即标定正确

### 4. 模板（救援区）

**必须在夹取距离、同样的畸变校正状态下**拍摄，且不要裁入过多背景：

1. 把车摆到夹取位置，机械臂到固定姿态
2. 分别拍摄圆柱 / 圆锥 / 腰鼓，保存为 `01.pgm` / `02.pgm` / `03.pgm`
3. 确认文件在 OpenMV 存储的根目录（不是 SD 卡子目录）

### 5. 巡线设定值

车摆正对中赛道，读画面 `LINE raw=...`，填入 `SETPOINT_X`。主控侧设定值 = `SETPOINT_X × 255 ÷ 319`。

### 6. 曝光系数

如果画面整体过曝（目标发白、边缘丢失），调小 `EXPOSURE_SCALE`；欠曝则调大。建议每次改 0.1 观察。

## 调试经验与踩坑记录

### 模板加载不能用 `copy_to_fb`

```python
# 错误：模板占用帧缓冲区，会被 sensor.snapshot() 每帧覆盖
_template = image.Image("01.pgm", copy_to_fb=True)

# 正确
_template = image.Image("01.pgm")
```

这是导致「模板匹配永远失败但看不出原因」的典型坑。

### `find_template` 返回值在不同固件版本不一致

- 旧版返回 match 对象：`r.x()` / `r.y()` / `r.rect()` / `r.score()`
- v4.7.0 返回元组：`r[0], r[1], r[2], r[3]`

代码用 `hasattr(r, "rect")` 做了兼容。

### 变焦镜头带来的连锁影响

- 桶形畸变会让边缘坐标偏移 → 可用 `img.lens_corr(strength)` 校正
- 但校正会**重映射整幅图**，此前标定的 ROI、夹取窗口、模板**全部需要重标**
- 放大后目标占像素更多，模板匹配变慢 → 优先加 `MATCH_STEP`

### 各模块分辨率不一致

QR 用 HD、rescue 用 VGA、其余用 QVGA。**切换分辨率后，该模块内所有 ROI 与夹取点坐标都要按比例换算。**

### 文件被占用导致保存失败

OpenMV IDE 打开文件时 Windows 会锁定，保存会失败并残留大量 `*.TMP` / `.bak_*` 文件。批量删除 `.TMP` 前先关闭 IDE；`.openmv_disk` 是磁盘标识文件，**不能删**。

### 帧率排查

画面左上角的 `FPS:xx.x` 是最直接的指标。救援模板匹配环节常见瓶颈：

| 帧率 | 判断 |
|------|------|
| ≥ 10 fps | 视觉伺服流畅 |
| 5~10 fps | 可用，但 PID 的 P 要调小 |
| < 5 fps | 需加大 `MATCH_STEP` 或缩小 ROI |

## 部署与运行

1. 将上述 `.py` 与 `.pgm` 文件拷贝到 OpenMV 存储根目录
2. 主程序命名为 `main.py`，OpenMV 上电自动执行
3. 串口接线：OpenMV `P4(TX)` → STM32 `RX`，`P5(RX)` → STM32 `TX`，共地
4. 波特率 `115200`
5. 上电后 LED 闪三下表示就绪，补光灯常亮
6. 主控发 `0x01` 开始任务

### 主控端解析示例

```c
/* 帧: A3 B3 cmd d1 d2 d3 C3（7 字节） */
if (buf[0] == 0xA3 && buf[1] == 0xB3 && buf[6] == 0xC3) {
    uint8_t cmd = buf[2];
    uint8_t d1 = buf[3], d2 = buf[4], flag = buf[5];

    if (cmd == 0x04 && flag == 1) {
        /* 救援目标到位，执行抓取 */
    }
}
```
